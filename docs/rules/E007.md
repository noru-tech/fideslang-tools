# E007: structure

**Severity:** error · **Checked by:** [`src/validate/rules/schema.rs`](../../src/validate/rules/schema.rs)

**Rule:** every resource must have a known resource type, the fields its type requires, and values of
the expected shape.

## What it checks

| Where | Requirement |
| --- | --- |
| Top level | The resource type is one of `organization`, `data_category`, `data_use`, `data_subject`, `dataset`, `system`, `policy` |
| Every resource | Is a mapping and has a string `fides_key` |
| `dataset` | Has a `collections` list; each collection is a mapping with a string `name` and a `fields` list; each field is a mapping with a string `name`, and its `data_categories`, if present, is a list |
| `system` | Has a string `system_type` and a `privacy_declarations` list; each declaration is a mapping with a single string `data_use`, and its `data_categories` and `data_subjects`, if present, are lists |
| `policy` | Has a `rules` list |

The messages say which requirement failed: `missing required field`, `must be a list, found string`,
`unknown resource type`, and so on.

## Why it matters

Fides and upstream's models reject a resource that is missing a required field or has a value of the
wrong type, so a manifest with E007 findings cannot be loaded as written. The other `fl` rules skip
parts they cannot read (a collection that is not a mapping has no fields to check for
[W002](W002.md)), so fixing E007 first makes the rest of the report complete.

## Controls

None. This is a manifest structure check.

## Failing example

[`tests/fixtures/invalid/e007_schema.yml`](../../tests/fixtures/invalid/e007_schema.yml):

```yaml
system:
  - fides_key: missing_type
    privacy_declarations:
      - name: no data_use
        data_categories: user.name
        data_subjects: [customer]
dataset:
  - fides_key: no_collections
widget:
  - fides_key: unknown_type
```

## Passing example

[`tests/fixtures/valid/e007_schema.yml`](../../tests/fixtures/valid/e007_schema.yml):

```yaml
system:
  - fides_key: typed_system
    system_type: Service
    privacy_declarations:
      - name: has a data_use
        data_use: analytics
        data_categories: [user.name]
        data_subjects: [customer]
dataset:
  - fides_key: with_collections
    collections: []
```

```console
$ fl validate tests/fixtures/valid/e007_schema.yml
OK 1 files, 2 resources checked against iab 3.0.0: 0 errors, 0 warnings
```

## How to fix

- Add the missing field. `system_type` is free text (`Service`, `Application`, `Database`, …).
- Write single keys as one-item lists: `data_categories: [user.name]`, not `data_categories: user.name`.
- A privacy declaration has exactly one `data_use`; split a declaration that needs two into two
  declarations.
- An unknown resource type is usually a typo (`systems:` for `system:`) or a file that is not a Fides
  manifest. Pass only manifest files, or narrow a directory with `--type`.

## Suppress or promote

E007 is already an error. `--allow E007` drops it, but the other rules may then miss problems in the
malformed resources.
