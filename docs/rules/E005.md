# E005: custom taxonomy self-reference

**Severity:** error · **Checked by:** [`src/validate/rules/custom_taxonomy.rs`](../../src/validate/rules/custom_taxonomy.rs)

**Rule:** a custom `data_category`, `data_use` or `data_subject` resource must not name itself as its
`parent_key` or its `replaced_by`.

## What it checks

`fl` compares `parent_key` and `replaced_by` with the resource's own `fides_key`. When `parent_key` is
the key itself, E005 is reported instead of [E004](E004.md).

## Why it matters

A record that is its own parent creates a cycle in the hierarchy, and one that replaces itself sends
anyone following a deprecation to the deprecated key. Upstream's models reject a self-referencing
`parent_key` (the `no_self_reference` validator).

## Controls

None. This keeps custom taxonomy extensions consistent with the Fideslang model.

## Failing example

[`tests/fixtures/invalid/e005_self_reference.yml`](../../tests/fixtures/invalid/e005_self_reference.yml):

```yaml
data_category:
  - fides_key: user.loop
    name: Self parent
    parent_key: user.loop
```

```console
$ fl validate tests/fixtures/invalid/e005_self_reference.yml
tests/fixtures/invalid/e005_self_reference.yml  data_category[user.loop].parent_key
  E005 `user.loop` cannot be its own parent
1 files, 1 resources checked against iab 3.0.0: 1 error, 0 warnings
```

A record with `replaced_by` equal to its own key is reported the same way, at `replaced_by`, with the
message `` `KEY` cannot replace itself ``.

## Passing example

[`tests/fixtures/valid/e005_real_parent.yml`](../../tests/fixtures/valid/e005_real_parent.yml):

```yaml
data_category:
  - fides_key: user.loop
    name: Loop
    parent_key: user
```

```console
$ fl validate tests/fixtures/valid/e005_real_parent.yml
OK 1 files, 1 resources checked against iab 3.0.0: 0 errors, 0 warnings
```

## How to fix

Set `parent_key` to the dotted prefix of the key (`user` for `user.loop`). For `replaced_by`, name the
key that replaces this one, or remove the field if nothing does.

## Suppress or promote

E005 is already an error. `--allow E005` drops it; upstream tooling would still reject the record.
