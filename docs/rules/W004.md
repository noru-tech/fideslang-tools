# W004: `data_purposes`

**Severity:** warning · **Checked by:** [`src/validate/rules/keys.rs`](../../src/validate/rules/keys.rs)

**Rule:** a manifest should list data uses under `data_uses`, not under the legacy field name
`data_purposes`.

## What it checks

`fl` warns about every key listed under a `data_purposes` field, at any depth. It still checks those
keys against the data uses in the taxonomy ([E001](E001.md), [W001](W001.md)), so a legacy manifest
gets a full report.

## Why it matters

`data_purposes` is an older name for the same thing. Tools that read data uses look for `data_uses`,
so keys left under `data_purposes` are likely to be ignored by them even though `fl` understands
them.

## Controls

None directly; see [E001](E001.md) for how data uses relate to the purposes in a record of
processing activities.

## Failing example

[`tests/fixtures/invalid/w004_data_purposes.yml`](../../tests/fixtures/invalid/w004_data_purposes.yml):

```yaml
dataset:
  - fides_key: legacy_purposes
    data_purposes: [analytics]
    collections:
      - name: t
        fields:
          - name: f
            data_categories: [user.name]
```


## Passing example

[`tests/fixtures/valid/w004_data_uses.yml`](../../tests/fixtures/valid/w004_data_uses.yml):

```yaml
dataset:
  - fides_key: current_uses
    data_uses: [analytics]
    collections:
      - name: t
        fields:
          - name: f
            data_categories: [user.name]
```

```console
$ fl validate tests/fixtures/valid/w004_data_uses.yml
OK 1 files, 1 resources checked against iab 3.0.0: 0 errors, 0 warnings
```

## How to fix

Rename the field to `data_uses`. If the resource already has a `data_uses` list, merge the two lists
and remove `data_purposes`.

## Suppress or promote

`--deny W004` (or `-W`) makes it fail the run. `--allow W004` drops it.
