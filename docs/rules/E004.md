# E004: custom taxonomy `parent_key` mismatch

**Severity:** error · **Checked by:** [`src/validate/rules/custom_taxonomy.rs`](../../src/validate/rules/custom_taxonomy.rs)

**Rule:** a custom `data_category` or `data_use` resource must declare a `parent_key` equal to the
dotted prefix of its `fides_key`, and a top-level key must declare none.

## What it checks

For each `data_category` and `data_use` resource in the manifest set, `fl` compares `parent_key` with
the key minus its last dotted segment (`analytics.reporting.custom` → `analytics.reporting`). It
reports a `parent_key` that differs, a missing `parent_key` on a dotted key, and a `parent_key` on a
key with no dot. `data_subject` resources are flat and are not checked. A parent that exists nowhere
is reported as [E001](E001.md).

## Why it matters

Fideslang builds its hierarchy from both the dotted key and `parent_key`, and upstream's models reject
a record where the two disagree (the `matching_parent_key` validator). A mismatch puts the custom
label in two places in the tree at once, so roll-ups, `fl taxonomy tree` and policies that match a
parent and its children give different answers.

## Controls

None. This keeps custom taxonomy extensions consistent with the Fideslang model.

## Failing example

[`tests/fixtures/invalid/e004_parent_key_mismatch.yml`](../../tests/fixtures/invalid/e004_parent_key_mismatch.yml):

```yaml
data_use:
  - fides_key: analytics.reporting.custom
    name: Custom Reporting
    parent_key: analytics
  - fides_key: marketing.custom_no_parent
    name: Missing parent
```

```yaml
data_use:
  - fides_key: analytics.reporting.custom
    name: Custom Reporting

  - fides_key: marketing.custom_no_parent

```

```console

```

## How to fix

Set `parent_key` to the expected value in the message. If the label really belongs under a different
parent, change the `fides_key` instead, so that its dotted prefix is that parent, and update every
manifest that uses the old key.

## Suppress or promote

E004 is already an error. `--allow E004` drops it; upstream tooling would still reject the record.
