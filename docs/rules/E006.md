# E006: invalid `fides_key`

**Severity:** error · **Checked by:** [`src/validate/rules/schema.rs`](../../src/validate/rules/schema.rs)

**Rule:** a `fides_key` may contain only ASCII letters, digits, `.`, `_`, `<`, `>` and `-`, and must
not be empty.

## What it checks

`fl` matches every resource's `fides_key` string against upstream's `FidesKey` pattern,
`^[a-zA-Z0-9_.<>-]+$`. A missing `fides_key`, or one that is not a string, is a structural problem
and is reported as [E007](E007.md).

## Why it matters

Upstream's models reject any other key (`FidesKeys must only contain alphanumeric characters, '.',
'_', '<', '>' or '-'`), so a manifest with one cannot be loaded by Fides. Keys also end up in URLs,
file names (`fl split --by resource` writes one file per key) and graph node IDs, where spaces and
slashes break things.

## Controls

None. This is a manifest syntax check.

## Failing example

[`tests/fixtures/invalid/e006_invalid_fides_key.yml`](../../tests/fixtures/invalid/e006_invalid_fides_key.yml):

```yaml
system:
  - fides_key: "has spaces/and slashes"
    system_type: Service
    privacy_declarations: []
```

```console
$ fl validate tests/fixtures/invalid/e006_invalid_fides_key.yml
tests/fixtures/invalid/e006_invalid_fides_key.yml  system[has spaces/and slashes].fides_key
  E006 invalid fides_key `has spaces/and slashes`: only letters, digits, `.`, `_`, `<`, `>` and `-` are allowed
1 files, 1 resources checked against iab 3.0.0: 1 error, 0 warnings
```

## Passing example

[`tests/fixtures/valid/e006_valid_fides_key.yml`](../../tests/fixtures/valid/e006_valid_fides_key.yml):

```yaml
system:
  - fides_key: no_spaces_or_slashes
    system_type: Service

```

```console
$ fl validate tests/fixtures/valid/e006_valid_fides_key.yml
OK 1 files, 1 resources checked against iab 3.0.0: 0 errors, 0 warnings
```

## How to fix

Replace the disallowed characters, usually with `_` or `-`, and keep the human-readable form in
`name`. Update every reference to the old key (`dataset_references`, `ingress`, `egress`,
`fides_meta`), or [E003](E003.md) reports them next.

## Suppress or promote

E006 is already an error. `--allow E006` drops it; Fides would still reject the key.
