# E003: dangling reference

**Severity:** error · **Checked by:** [`src/validate/rules/references.rs`](../../src/validate/rules/references.rs)

**Rule:** every reference from one resource to another must name a resource that is loaded in the
same run.

## What it checks

| Field (at any depth) | Must name |
| --- | --- |
| `dataset_references` | a `dataset` |
| `ingress`, `egress` (strings, or data flows with `fides_key`) | a `dataset` or `system`, or the built-in endpoint `user`; a data flow with `type: dataset` or `type: system` must name that type |
| `fides_meta.references[].dataset` | a `dataset` |
| `fides_meta.after`, `erase_after` on a dataset | a `dataset` |
| `after`, `erase_after` under a dataset's `collections` | a `dataset.collection` pair whose dataset and collection both exist |
| `organization_fides_key` | an `organization`; `default_organization` is always accepted, and the check is skipped when the manifest set declares no organizations |

## Why it matters

References are the edges of the data map: which datasets a system uses, where data flows in and out,
and in which order Fides processes datasets and collections when it runs a privacy request. A
reference to something that is not there draws an edge to nowhere in `fl graph`, and a tool that
follows it fails or silently skips that step.

## Controls

None directly. Data flows can feed documentation of recipients and transfers, so a broken edge is a
gap there; `fl` checks only that the target exists.

## Failing example

[`tests/fixtures/invalid/e003_dangling_reference.yml`](../../tests/fixtures/invalid/e003_dangling_reference.yml):

```yaml
system:
  - fides_key: dangling_refs
    system_type: Service
    dataset_references: [no_such_dataset]
    ingress:
      - fides_key: no_such_system
        type: system
    privacy_declarations:
      - name: ok
        data_use: analytics
        data_categories: [user.name]
        data_subjects: [customer]
        egress: [nowhere]
```

## How to fix

- Most often the target lives in another file: pass every file or the whole directory in one run
  (`fl validate .fides/`). References are resolved across all loaded files.
- If you narrowed the run with `--type` or `--key`, the target may have been filtered out. Run without
  the filter to check references.
- Otherwise correct the key, declare the missing resource, or remove the reference. `fl cat PATH
  --type dataset,system --format tree` lists what is loaded.

## Suppress or promote

E003 is already an error. `--allow E003` drops it, which is reasonable only when you validate a
partial manifest set on purpose and the targets live elsewhere.
