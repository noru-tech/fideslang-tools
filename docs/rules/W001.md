# W001: deprecated taxonomy key

**Severity:** warning · **Checked by:** [`src/validate/rules/keys.rs`](../../src/validate/rules/keys.rs)

**Rule:** a manifest should not use a taxonomy key that the taxonomy marks as deprecated.

## What it checks

Every key that [E001](E001.md) looks up is also checked for a `version_deprecated` in the taxonomy
(bundled or custom). The message gives the version that deprecated it, and the suggestion names the
`replaced_by` key when the taxonomy records one. In the bundled fideslang 3.0.0 taxonomy the only
deprecated key is the data use `personalize.profiling`; `fl taxonomy list all --deprecated` lists
them, including any your custom taxonomy resources deprecate.

## Why it matters

A deprecated key still resolves, so nothing breaks today, but upstream has said where the label
should go instead and may remove it in a later release. Moving now keeps the data map aligned with
what other Fideslang tools expect.

## Controls

As for [E001](E001.md): if you derive a record of processing activities from the manifests
(GDPR Art. 30(1)(b) and (c)), a deprecated purpose or category still describes the processing but
uses wording upstream has retired.

## Failing example

[`tests/fixtures/invalid/w001_deprecated_key.yml`](../../tests/fixtures/invalid/w001_deprecated_key.yml):

```yaml
system:
  - fides_key: deprecated_use_system
    system_type: Service
    privacy_declarations:
      - name: profiles for content
        data_use: personalize.profiling
        data_categories: [user.behavior]
        data_subjects: [customer]
```

```console
$ fl validate tests/fixtures/invalid/w001_deprecated_key.yml
tests/fixtures/invalid/w001_deprecated_key.yml  system[deprecated_use_system].privacy_declarations[0].data_use
  W001 data use `personalize.profiling` is deprecated since 2.1.1 — use `personalize.content.profiling`
1 files, 1 resources checked against iab 3.0.0: 0 errors, 1 warning
```

The run exits `0`: warnings do not fail it unless promoted.

## Passing example

[`tests/fixtures/valid/w001_current_key.yml`](../../tests/fixtures/valid/w001_current_key.yml):

```yaml
system:
  - fides_key: current_use_system
    system_type: Service
    privacy_declarations:
      - name: profiles for content
        data_use: personalize.content.profiling
        data_categories: [user.behavior]
        data_subjects: [customer]
```

```console
$ fl validate tests/fixtures/valid/w001_current_key.yml
OK 1 files, 1 resources checked against iab 3.0.0: 0 errors, 0 warnings
```

## How to fix

Replace the key with the one in the suggestion. `fl taxonomy show KEY` shows the deprecation version
and the replacement. Check that the replacement still describes your processing; a replacement is
sometimes narrower or broader than the old key.

## Suppress or promote

`--deny W001` (or `-W` for every warning) makes it fail the run. `--allow W001` drops it.
